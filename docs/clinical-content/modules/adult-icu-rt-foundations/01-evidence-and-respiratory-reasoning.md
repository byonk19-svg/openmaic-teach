# Module 01: What do we actually know? Patient, support, and respiratory evidence

> State: Generated draft. This brief is not clinical-ready instruction and must not be used as patient-specific advice.

## Purpose

Establish the reasoning behavior required by every later clinician-track module: distinguish what the available respiratory information establishes from what remains inferred, uncertain, or in need of reassessment, communication, or escalation.

## Learner and prerequisites

This module is for practicing adult acute/ICU respiratory therapists with baseline ventilator and ABG literacy. It is a clinician refresher, not introductory RT-school instruction, a competency assessment, or a procedural authorization.

## Draft objectives

By the end of the module, the learner should be able to:

1. Classify relevant case information as observed, set, measured, calculated, or modeled.
2. State one clinically consequential uncertainty or validity condition before inferring a respiratory conclusion.
3. Distinguish a programmed setting from a device-displayed delivery value and explain what further evidence is needed.

These are generated-draft objectives. Any clinical assertion, example, or feedback that supports them requires a source record before qualified RT review.

## Learning arc

1. **Original visual:** patient, respiratory support, information source, timestamp, and uncertainty shown as separate layers.
2. **Worked synthetic case:** a set value, a device-displayed value, an observed finding, and a missing measurement are deliberately distinguishable.
3. **Reasoning checkpoint:** classify each datum and select the most consequential uncertainty; do not reveal an intervention.
4. **Targeted feedback:** name the specific provenance error, explain the missing/invalid comparison, and state what information would improve the assessment.
5. **Spaced transfer:** change one condition—such as timing, signal quality, support level, or patient effort—while requiring the same provenance reasoning.

## Draft opening case constraints

The case must be explicitly synthetic and include:

- a clinician-programmed respiratory-support setting;
- a separately displayed device-derived value from a defined time window;
- an observed patient finding with source and timing;
- a measurement whose validity context is supplied;
- one deliberately absent datum that the learner must not invent.

The exercise may use arithmetic only when all inputs, units, time windows, and assumptions are visible. A calculated value must never be presented as proof of adequate gas exchange, effort, or safety.

## Non-goals

This module does not teach a treatment algorithm, prescribe ventilator changes, establish a diagnosis, teach device-specific behavior, or certify a learner as clinically competent.

## Required evidence and review gate

Before clinical-ready labeling, create source records for every consequential assertion and dependent asset, then obtain a completed qualified RT review decision for the exact content version. Use only original product-authored visuals unless a source record documents reuse permission.
